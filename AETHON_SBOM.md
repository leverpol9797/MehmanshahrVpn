## SBOM findings

### SBOM-1 - LOW

**Statement.** src-tauri/Cargo.toml has no `license` field, so `cargo metadata` reports the root crate's license as unstated while the repository LICENSE is AGPL-3.0.

**Impact.** Any generated SBOM, crates.io publish, or downstream license scan sees no license for the application crate.

**Fix.** Add `license = "AGPL-3.0-only"` to [package] in src-tauri/Cargo.toml. Not applied here: declaring a licence is the copyright holder's call, not an auditor's.

### SBOM-2 - LOW

**Statement.** third-party/sing-box-LICENSE.txt is tracked but sing-box is referenced nowhere in the product.

**Impact.** Documentation drift. A reader or an automated scanner could conclude sing-box ships when it does not.

**Fix.** Delete the file, or add a line to NOTICE.md explaining why it is retained. Not applied here: deleting a tracked license file is a licensing/compliance decision for the owner.

### SBOM-3 - LOW

**Statement.** NOTICE.md attributes SHA-256 15c2d007...ef8b1 to "its unmodified official Windows archive". That digest is the extracted xray.exe (routing.rs XRAY_SHA256). The ARCHIVE digest is d004c39288ce9ada487c6f398c7c545f7d749e44bdfdd59dbc9f865afba4e1ad per scripts/fetch-xray.ps1.

**Impact.** A reader verifying the notice against the downloaded zip gets a mismatch and could wrongly conclude the archive was tampered with. Both digests are individually correct and both are enforced by fetch-xray.ps1; only the label in NOTICE.md is wrong.

**Fix.** Relabel in NOTICE.md: archive d004c392..., xray.exe 15c2d007...

### SBOM-4 - MEDIUM

**Statement.** tauri.conf.json bundle.resources lists ../third-party/xray-LICENSE.txt and ../third-party/wintun-LICENSE.txt, and neither file is tracked in git (both are `??` in git status).

**Impact.** A fresh clone of commit 95d50e41 does not contain these two files, so the bundle step has to resolve literal resource paths that are not in the repository. This is the same root cause as the atomic-commit defect in the remediation report: the working tree builds, a clean clone is not proven to.

**Fix.** Commit third-party/xray-LICENSE.txt and third-party/wintun-LICENSE.txt with the rest of the atomic set. They are generated by scripts/fetch-xray.ps1, which copies them out of the verified archive.

### SBOM-5 - MEDIUM

**Statement.** Because of SBOM-4, the two third-party licence texts that tauri.conf.json ships as bundle resources are not in source control. Wintun's licence is a bespoke WireGuard LLC licence whose clause 3(c) forbids removing proprietary notices and whose clause 3(d) permits redistribution only alongside software using the Permitted API.

**Impact.** A build from a clean clone would be missing the Wintun and Xray licence texts it is required to deliver, so the resulting installer could ship a redistributed proprietary DLL without its notice. This is a licence-compliance exposure, not just a build-input gap.

**Fix.** Same fix as SBOM-4 (commit both files), plus verify after the next build that both licence texts are present inside the NSIS and MSI payloads, which the PHASE 7 payload extraction already has a method for.
